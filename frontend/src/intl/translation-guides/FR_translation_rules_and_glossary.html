2. Règles de traduction

#

Règle

Notes

1

Formes genrées

Éviter les formes genrées et l’ajout de parenthèses dans les libellés UI pour ne pas alourdir l’interface. ✅ Patient, Clinicien, Alloué.. ❌ Patient(e), Praticien(ne), Alloué(e)...

Exception pour les messages longs ou textes explicatifs.

2

Format des libellés courts (colonnes, champs)

Pas d'article défini au début des libellés courts.

Abréviations pour les en-tête : Cond., CMM, ..

3

Utilisation du Slash

Lorsque le slash est utilisé pour signifier ‘par’, ajouter un espace de chaque côté: ✅Unités / Cond. (=pack size) ❌Unités/Cond.

4

Messages d'erreur et de confirmation

Si possible, commencer la description par l'action impossible : ✅ Importation impossible : le statut doit être ‘Créé’ ❌Il est impossible d'importer car le statut n'est pas ‘Créé’.

5

Importer / Exporter VS Téléverser / Télécharger

Téléverser = envoyer un fichier vers le serveur

Importer = charger des données dans le système

Télécharger = sauvegarder un fichier sur l'appareil

Exporter = extraire des données du système vers un fichier

6

Accentuation obligatoire

Toujours utiliser les accents quand c’est possible: ✅Évolution (avec accent) ❌jamais Evolution.

7

Majuscules

Les statuts prennent une majuscule initiale : Créé, Finalisé, Envoyé…

Les libellés de colonnes : majuscule au premier mot uniquement ✅ Date d'expiration ❌ Date D'Expiration.

Les acronymes restent en majuscules : CMM, GAPS, PCV, VEN…

8

Termes à ne pas traduire (garder en anglais)

Legacy (code/clients legacy), LogTag (marque), Laird (marque), Noms de marques et produits propres, Identifiants techniques et codes.

9

Cohérence des confirmations UI

Préférer la forme affirmative courte pour les boutons : ✅ Confirmer la finalisation ❌ Êtes-vous sûr(e) de vouloir finaliser ?

10

Mots à éviter

Si possible, éviter les termes génériques (e.g., Quantité) à moins que l’unité et le contexte y soit clairement définis.

Par défaut, ‘stock’ se réfère à un nombre d’unités.
