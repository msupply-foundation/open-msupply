# UI elements — what each is built from

A living ledger of every UI element built in this app and **what went into it** — hand-rolled plain HTML/CSS vs. a headless library part, and _why_ a library was used where it was. Update this whenever an element is added or its composition changes. (Same convention as the RnD prototype's `UI_ELEMENTS.md`.)

> **Convention.** Default is **hand-rolled**: plain semantic HTML + CSS Modules + design tokens (`src/ui/styles/tokens.css`), sized in rem. We reach for a **headless** primitive only where the widget has a real accessibility/interaction contract that's tedious and risky to hand-roll (and that WCAG 2.2 grades). When we do, **we still own all the markup and CSS** — the library supplies behaviour + ARIA, not a look.
>
> **The WCAG 2.2 AA bar applies to every element in this table, hand-rolled or headless** (principle #9 in `CLAUDE.md`). Buying a headless primitive is how we meet it for the hard widgets; it is not the only place a11y matters. Hand-rolled elements owe the same duties — semantics + accessible name, keyboard operability, visible focus, AA contrast in both themes, no colour-only meaning.

## Cross-cutting (not a single element)

- **Design tokens** — `src/ui/styles/tokens.css`, ported from the RnD prototype (itself a faithful port of the current app's `theme.ts`), restructured with an enforced **theme contract** region (see [`kdd/ui-styling`](../../../kdd/ui-styling/draft-kdd.md)). Includes the dark theme with the inverted-surface elevation model (`--surface-raised`, near-black dark shadows), and the six `--status-*` shipment-status colours (StatusChip; demo values pending a designed palette).
- **Root stylesheet** — `src/index.css`: box-sizing reset, the single root font-size knob (rem scaling; phone < 600px drops root to 85%), body defaults from tokens, Inter Variable via `@fontsource-variable/inter`.
- **CSS integrity tooling** — `npm run check`: typed-css-modules `.d.ts` generation → `tsc -b` → stylelint (incl. unknown-`var()` detection against `tokens.css`) → theme-contract script → page-CSS check (`scripts/check-page-css.mjs`: pages own no CSS — see [`kdd/page-composition`](../../../kdd/page-composition/draft-kdd.md)). See [`kdd/ui-styling`](../../../kdd/ui-styling/draft-kdd.md).

The **only** JS that touches responsiveness, and only for "which element renders" decisions (principle #7); everything visual stays in CSS. Ported from the prototype's `useMediaQuery`/`breakpoints`.
- **Favicon** — `public/favicon.svg` is the MSupplyGuy brand mark (same paths/gradient as the `MSupplyGuyLogo` icon), replacing the Vite/Solid default so the browser tab matches the app.
