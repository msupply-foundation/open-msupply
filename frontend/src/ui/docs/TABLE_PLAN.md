# Tables reconciliation — implementation plan (Phases 2–4)

The working plan for aligning the shared [`DataTable`](../elements/table/DataTable.tsx) to the org design standard's **Tables** section (https://msupply-foundation.github.io/ui-standards/#tables), continuing from the completed Phase 1. Process rules live in [`DESIGN_STANDARDS.md`](./DESIGN_STANDARDS.md) — in particular: **work from the raw upstream HTML/CSS, never a WebFetch summary** (pull the `#tables` section's literal values; the demo tables' inline `<style>` blocks carry the concrete numbers), land every value as a token, and verify by rendering. Phase decisions and scope in this file are Carl's (2026-07-23).

## Where things stand — Phase 1 done (2026-07-23)

Structural chrome is in (see the Tables entry in [`DESIGN_STANDARDS.md`](./DESIGN_STANDARDS.md) › Ledger for the full record):

- The **DataTable is the composition root of its own chrome**: toolbar (page-composed `filters` slot inline-start; exactly **three** controls inline-end — Columns popover, Settings popover, full-screen), the content scroll box, and **one footer bar** (`ContentFooter` reused: pager by default ⇄ "N selected" + page-supplied `selectionActions` + Clear while rows are selected). The floating pager overlay is gone ([`kdd/table-state`](../../../kdd/table-state/draft-kdd.md) records the reversal).
- **Columns popover** = Show all / Hide all + per-column Show · Move ↑↓ · Pin L/R (no width input — width is header-edge drag). **Settings popover** = Density radio (Comfortable ⭐ / Compact / Spacious — functional: `viewDensity` config → `data-density` → 52/40/64px row heights) + the single **"Reset table to default"** (disabled at default via `configIsDefault`/`isConfigDefault`; clears the user layer with `setConfig(key, undefined)`, NOT TanStack `reset*`) + admin save-as-global-default.
- Select-all checkbox sets the DOM **`indeterminate`** property; the single-level filter menu → empty-chip model is a **recorded deliberate divergence** from the spec's nested add-filter editor (most filter values need a follow-up query for options). **Global search dropped for now** (Carl).
- **Migrated to the new composition:** `InboundShipmentsList` (reference) + `TableShowcase` + `DetailTableShowcase`. Filter/sort/pagination state stays page-owned and URL-backed (`useUrlQueryState` — verified live; the showcase's local signals are a stand-in, not the pattern).
- **Phase 1 follow-ups still open** (fold into whichever phase touches them, or do as chores): migrate the remaining list pages to `filters`/`selectionActions` — selectable: `outbound-shipments`, `customer-returns`, `stocktakes`, `locations`; read-only: `items`, `stock`, `patients`, `master-lists` (pager-only footer). Detail views + link modals keep the in-table footer automatically. The card/table **view switch** was removed from the toolbar (returns in Phase 4); card view still auto-activates via the compact band's `viewMode: 'card'` default.

## Phase 2 — styling to match the design spec (incremental, element by element)

Style every table element to the spec, **one element at a time so Carl can review each individually** — including each cell-type component. Suggested review queue (one PR-able unit each; order negotiable):

1. **Header row** — bg/typography/line-height (`1.43`), vertical centring; the spec's `#FAFAFA`-family near-hues stay deferred to the colour/Typography pass (use existing tokens).
2. **Sort indicator** — reserved, always-present slot (fixed width so headers never shift), blue `--secondary-main` ▲/▼ at the spec's `1.125rem`; sortable-header hover wash.
3. **Body rows: base + hover** — hover wash `rgba(0,0,0,0.04)`-equivalent via tokens (`color-mix` is fine — the old Chromium <111 overlay rule is retired, see [`kdd/ui-styling`](../../../kdd/ui-styling/draft-kdd.md)), `transition: background 0.15s` with reduced-motion respect.
4. **Selection + semantic row states** _(decided 2026-07-23, Carl — adopt in full)_: **selected flips to blue** (currently the orange `--primary-main` tint) and add the badge-paired semantic tints — `verified` (green), `warning` (amber), `disabled` (grey bg + legible `#616161`-class text + `not-allowed`); one status tint at a time, never stacked; errors are field-level, not a row tint. Fold `rowDimmed` → disabled; keep `rowTone` (info/error text). New `rowState` prop stamped as `data-row-state`; opaque pinned-cell variants of every tint.
5. **Density paddings + typography** — the spec's per-density cell padding (compact `8px 12px` · comfortable `12px 16px` · spacious `16px 20px`; row heights already live), body cell `line-height 1.43`, `vertical-align` (headers middle, multi-line cells top). Also the **responsive default**: grow to Spacious at ≤1023px via a width query (mirrors the Buttons touch-growth precedent) with an explicit user choice winning.
6. **Numbers** — `font-variant-numeric: tabular-nums` on right-aligned cells (header/body/footer; keyed off the existing `data-align='right'` — no new column flag).
7. **Empty cells → blank** _(decided 2026-07-23, Carl)_: drop the `—` placeholder in [`tableHelpers.tsx`](../elements/table/tableHelpers.tsx) (`getDateCell`/`getExpiryDateCell`/`getCurrencyCell`/`getFlagCell`; comment cell already renders nothing). Real zeros still show `0`; short "N/A" only where _not applicable_ ≠ _no value_ (note the convention in the helper comments).
8. **Cell-type components, one by one** — StatusChip-in-cell, date/expiry (near-expiry error tone), currency, comment (icon + popover), boolean/flag, chip-list, linked-order link — each checked against the spec's alignment table (text/dates left · numbers/currency/percent right+tabular · status left-or-centre · booleans centre; right-aligned cells ⇒ right-aligned headers).
9. **Selection checkbox** — the spec's blue-accent control (`accent-color: --secondary-main`), leading column at the spec's ~3rem/48px fixed box (update `--table-leading-col` + the mirrored JS px in `DataTable.tsx`).
10. **Filter bar + chips** — the spec's compact chip look (`Label: value ▾` pill, `rgba(62,123,250,0.10)` blue family, rounded, hover; dashed "Add filter" pill; "Clear all" text button). Keep the single-level/empty-chip behaviour; this item is look-only.
11. **Toolbar + footer bands** — toolbar spacing/border treatment against the scroll box; footer band (currently raw `ContentFooter` — fix the double hairline where the scroll-box border meets the footer's top border); pager layout per spec (rows-per-page + range + pills + arrows; ≤480px collapse to prev/next + range is a candidate here or later).
12. **Column resize handle + drag affordances** — confirm hit area/bar vs spec (`0.75rem` target, `0.125rem` blue bar); header drag-to-reorder (grab cursor + drop indicator) is a spec feature we don't have — decide adopt/defer. **Double-click-to-auto-fit landed** (issue #651): the divider's second press snaps the column to its widest rendered content instead of starting a drag (measured in `DataTable.autoFitColumn`, bounded by `autoFitWidth.ts`) — it writes the same `size` a drag writes, so it persists and resets identically, and it inherits the flex-sink limitation below. Still no non-pointer alternative (the WCAG 2.5.7 TODO in `DataTable.module.css` covers both gestures).
13. **Control popovers** — the toolbar's Columns/Settings panels + their trigger buttons styled to the spec's popover look (`.mrt-pop`/`.mrt-ib`: white panel, `0.5rem` radius + soft shadow, muted `0.6875rem` section titles, dense hover rows, blue accents/`accent-color`, active-trigger tint). Look-only — the structure and contents landed in Phase 1.

Each item: fetch that sub-section raw → diff → conflicts to Carl → implement against tokens → `pnpm check` → render-verify (showcase `#/showcase/table` + `#/showcase/detail-table`, light + dark, and the real inbound list) → ledger row in `DESIGN_STANDARDS.md`.

## Phase 3 (changed) — a Column config API

Design a specific column-configuration API. Primarily **TanStack column configs as they are today** (the `Column<T,K,G>` model in [`columnTypes.ts`](../elements/table/columnTypes.ts) — typed identity `c:` union + `sortKey` + `meta`), plus conveniences:

- **A map of pre-defined columns** — e.g. a "Status" column always gets the same config (header key, StatusChip cell, alignment, width class) so verticals stop re-declaring it. The existing cell fragments in [`tableHelpers.tsx`](../elements/table/tableHelpers.tsx) (`getNumberCell`/`getDateCell`/`getCurrencyCell`/`getCommentCell`/`getFlagCell`/`getExpiryDateCell`) are the natural seeds — the pre-defined map likely composes identity + header + fragment + width in one place. Candidate pre-defined columns to inventory from real pages: status, created/delivered/expiry dates, invoice/number, comment, reference, total/currency, item code/name, batch, pack size, location, unit, selection.
- **Intelligent column widths** — different column types get pre-specified widths instead of ad-hoc per-page values. The spec's width table is the source: codes/IDs `5–8.75rem` · item names flexible (`min 18.75rem`) · numbers `6.25–7.5rem` · dates `8.125rem` · status `7.5–9.375rem` · checkbox fixed 48px. Decide how a "width class" interacts with the existing rem-based `columnSizing` config (user overrides via header-drag persist per band; type widths are the _defaults_ underneath), TanStack's `getSize()` min-width floor, and auto table layout.
  - **Known limitation to resolve here (Carl 2026-07-24):** under the current `min-width`-floor + auto-layout model, the **flex-sink column can't be dragged narrower** — the widest-content column (e.g. inbound/showcase "Name") absorbs all the table's slack, so lowering its floor just re-absorbs the freed space and it snaps back. Growing works (damped); shrinking below its content/flex width doesn't. Other columns shrink fine once grown. Double-click auto-fit (unit 12) hits the same wall from the other side: fitting the sink column narrower re-absorbs the slack, so its width doesn't visibly move. The fix (deferred from unit 11 into this phase): give a _resized_ column explicit `width` semantics so it stops flex-absorbing and becomes draggable both ways — decide against the type-width defaults + whether the table still fills 100% once columns are user-sized.
- Keep the type-safety bar ([`kdd/type-safety`](../../../kdd/type-safety/draft-kdd.md)): the map must not weaken `keyof T` checking or the `K` sort-key inference; per-vertical overrides stay explicit (kdd/explicit-composition — a pre-defined column is a convenience seed, not a config-driven field mapper).

Deliverable: a short design doc / KDD (fork test applies — there are real rejected alternatives here) agreed with Carl before the refactor sweep across the ~40 DataTable call sites. **Landed 2026-07-24:** the API is built (`getCellDefinition` + `_globalColumnConfig.ts`), documented in [`CELL_TYPES.md`](./CELL_TYPES.md), and the decisions are captured in [`kdd/column-config`](../../../kdd/column-config/draft-kdd.md). Still open: the flex-sink-can't-shrink limitation (KDD records the options — accepted "as is" for now) and the call-site sweep (Carl to roll the presets out to the verticals separately).

## Phase 4 — Card view

**Infrastructure + styling landed 2026-07-26 (Carl).** The card view is rebuilt around a per-column **group** model; the old `tabsAndCardGroups` tab machinery is deleted.

**The card model** ([`columnTypes.ts`](../elements/table/columnTypes.ts), [`CardView.tsx`](../elements/table/CardView.tsx)) — the implementation API (per-column `headerPosition`/`showLabel`/`cardGroup`/`hideOnCard`/`hideOnTable`, table-level `cardGroups`, and the group presentation fields), with worked recipes, now lives in **[`CARD_TABLE_MODEL.md`](./CARD_TABLE_MODEL.md)**. This section keeps only the Phase-4 decisions and what was removed:

- Renamed the old `cardPosition` → `headerPosition` (now header-only — the four-value `content-*` set was never used, so nothing lost). `cardGroup` replaced the old per-column tab membership as a typed top-level `Column` field.
- **Deleted with the tab model:** `tabsAndCardGroups`, `ALL_TABS`, `Membership`, `TabAndCardGroup`, the toolbar tab strip, `selectedTab`/`activeTab`, `columnInActiveTab`. Table view no longer filters by group (a page wanting tabbed column subsets renders a table per tab itself — Carl 2026-07-25). NB the `kdd/edit-line-card-table` the old code cited **never existed as a file** (comment-only).

**View switching + toolbar** ([`DataTable.tsx`](../elements/table/DataTable.tsx)):

- `viewMode` (config): **below the compact 600px band the table is ALWAYS card** (`useIsCompact`), toggle hidden; above, `config.viewMode ?? 'table'`. A page defaults card-by-default by seeding base-band `viewMode: 'card'`.
- **View toggle** returned as a SINGLE borderless Card-view button matching the other control icons (grey → blue-active), not a segmented pair (Carl 2026-07-26); opt-in per table via **`showCardToggle`** + `setConfig`, above the band only.
- **Sort control** — card view has no clickable headers, so a labelled Sort **pill** (min-width `6rem`; field name inline-start, the table header's own `↓`/`↑` `.sortIndicator` glyph pinned inline-end) opens a popover of the sortable columns (those with `sortKey`), calling the same `onSort` — no new state. Auto-shown when card view + `onSort` + sortable columns. Toolbar `flex-wrap`s; control-cluster gap `--space-1`, the pill gets extra `margin-inline-end`.

**Styling** — ui-standards `#table-cards` (`.card-table-*`) for the card anatomy + tonight's stocktake mockup (`.bc-zone`/`.bc-more-toggle`) for panels/disclosure, both mapped to tokens:

- Discrete card **boxes** (`--surface-raised` + `--color-border-value` + `--radius-md`) on a recessed grey list — new token **`--table-card-surface`** (light + dark), applied via `data-view='card'` on the scroll area only. Header → body **hairline division** (`.cardBody` border-top). Identity title `--text-md`; header `align-items: center`. **Selected** card = blue border + faint blue fill (`--secondary-main` 40%/5%), replacing the old whole-cell tint.
- Field grid is `repeat(auto-fit, minmax(…, 1fr))` (two columns on a phone card, more on a wide/modal card) — `7rem` floor for flat read fields (denser), `10rem` inside panels (editable inputs need the room). Panels: faint fill + hairline + `--radius-md`. Disclosure trigger restyled to the mockup's inline blue link (`.card .cardDisclosureTrigger` out-specifies the shared `Accordion .trigger`).
- **NB the spec's own field-label (`.card-table-field-label`) is `0.6875rem` BLUE, `text-transform: none`** — NOT uppercase (the earlier note here was wrong). We did NOT adopt that; instead labels were unified with input labels (below). No "code-beneath-identity" slot was added (not in the column model; revisit if wanted).

**Shared field-label token** (Carl 2026-07-26): **`--field-label-*`** (size/weight/line-height/colour) in [`tokens.css`](../styles/tokens.css) is the ONE definition of a field label, referenced by every input's `.label` (`TextField`/`TextArea`/`DateTimeFields`; `NumberField` wraps `TextField`) **and** [`LabelledValue`](../elements/typography/LabelledValue.tsx) — so a read-only labelled value and an editable input read identically. `LabelledValue`'s `card`/`field` variants now differ ONLY in the label→value gap. (Consequence: read-only card labels rose from `--text-xs`/muted to the input style `--text-sm`/`--text-body`; it's one token to retune. Small inputs still notch to `--input-font-sm` — a size variant.)

**Migrations:** both line-edit modals ([Inbound](../../../src/sections/inbound-shipments/detail/edit-modal/InboundShipmentLineEditModal.tsx), [Stocktake](../../../src/sections/stocktakes/detail/edit-modal/StocktakeLineEditModal.tsx)) moved to `cardGroups` (batch = always-shown panel; pricing/other = closed disclosures with their icons) + base `viewMode: 'card'`. Originally card-only with no toggle; **#886 added `showCardToggle` to both plus [Outbound](../../../src/sections/outbound-shipments/detail/edit-modal/OutboundLineEditModal.tsx)** — cards stay the default, the table is a persisted per-user opt-in above the compact band. `cardPosition`→`headerPosition` swept across ~30 call sites. New testids `table-view-toggle`/`table-sort`/`table-sort-<sortKey>` (see the constraints line); new keys `table.sort`, `table.more-details`.

**Still open / handed to the next session (the Edit Line batch view):** wire up `disclosurePreview` (built but unexercised anywhere yet) and any per-group `panel`/box-per-group refinements when the modal batch cards get their real treatment. Column priorities (P1/P2/P3 responsive auto-hide) still park here — manual per-band `columnVisibility` stands in.

**Known cross-browser note (not a bug):** the card header's checkbox/dot/icon/title are box-centred and every box centre is identical in Chromium AND Firefox (measured). Any residual glyph-within-box offset is the rasteriser's leading distribution, which differs per engine in opposite directions, so a `line-height` tweak helps one and regresses the other — left at the default (documented in [`DataTable.module.css`](../elements/table/DataTable.module.css) `.cardPrimary`). `text-box-trim` (leading-trim) would fix it but is Chromium-only and doesn't reach the showcase cell's nested inline-flex name anyway.

## Standing constraints (apply to every phase)

- Colours only from tokens (literals only in `tokens.css`; new tokens need dark overrides). `color-mix` is fine (Chromium-floor rule retired 2026-07-23). rem/em only — px for hairlines/radius/shadows.
- Bundle size is load-bearing; no new dependencies for any of this.
- Keep the cross-FE test ids stable ([`e2e/TESTIDS.md`](../../../e2e/TESTIDS.md)) — the table ids added in Phase 1: `table-footer`, `table-reset-default`, `table-density-<density>`, `table-show-all-columns`/`table-hide-all-columns`; Phase 4 added `table-view-toggle`, `table-sort`, `table-sort-<sortKey>`.
- Verify by rendering (dev server :3005), light + dark, desktop + ≤1023px + <600px, per the `DESIGN_STANDARDS.md` loop; flip the Tables status row / extend the ledger as each phase lands.
