# Build report — immunisation-programs

**Target stack:** SolidJS + Vite; shared component library `src/ui/`, every slot resolved through the roles in [`spec/ui-standards/components.md`](../../../spec/ui-standards/components.md).

Scoped build of the immunisation-programs vertical from [`spec/immunisation-programs`](../../../spec/immunisation-programs/README.md) (authored on `fe/346-immunisations-spec`, which this branch is stacked on). The vertical is the central server's immunisation catalogue at `programs/immunisations`: the program list (S1), a program's course list (S2), the course editor dialog (S3) with its per-store rates panel (S3a), and the delete confirmation (S4). Types generated by `pnpm codegen` against the pinned `spec/schema.graphql`; the pass rewrote no other vertical's `.generated.ts`.

**Gates: all three green.** `pnpm check` · `pnpm test` (3721 tests, 310 files, including 66 in this section) · `pnpm build` (the section is two chunks: `ProgramsList` 2.97 kB, `ProgramDetail` 23.7 kB raw).

## Built

- **S1 program list** (`ProgramsList.tsx`) — the standard list screen: `Page` + `Header`(`Breadcrumb`) + `DataTable`. Columns Program name (sortable, the default ascending sort) · Vaccine courses (the program's live course names, comma-separated; blank when none). Server-paginated, URL-backed state via `useUrlQueryState`. One filter — Program name, a case-insensitive contains — through the table toolbar's `FilterBar`. Row click navigates to S2.
  - **Three spec'd deviations from the standard list**: **no page actions** (programs are legacy master data; nothing here creates or exports one), **no selection column / bulk bar**, and **no sort on Vaccine courses** (`ProgramSortFieldInput` has only `name`, so the generated sort-key type is the literal `'name'`).
  - **`isImmunisation: true` is forced onto every read** and is not a user filter; `ProgramSortInput` is always sent (the no-sort default is id order — wire trap); `vaccineCourses: null` is read as "none" (wire trap). All pinned in `programRegister.test.ts`.
- **S2 program detail** (`ProgramDetail.tsx`) — the program's course list under the two-crumb trail _Immunizations › {program}_ (the parent crumb links back; no action-footer Close, per D103). Columns Name (sortable) · Target demographic · Doses (the live count, a number cell). New vaccine course in the header and the empty state's _Create a new one_ open S3 blank; a row opens S3 on the course; a selection offers **Delete** in the table's own selection bar. Exactly one sort entry is always sent (the resolver applies the last — wire trap); the selection is deleted in **list order** (`inListOrder`).
- **S3 course editor** (`CourseEditModal.tsx`) — one `Dialog` (`width="wide"`) for create and edit; the draft is a `createStore` over the generated course node, widened only for cleared rates and non-null lists (`courseEditor.ts`). Fields: Vaccine course name (`TextField`) · Target demographic (`Combobox` over every group, clearable) · Coverage rate · Wastage rate (`NumberField`, `%`, 1 dp; neither capped at entry — above 100 the wastage rate is named _too large_ and the save refused) · **Configure per store** · Vaccine items (`MultiSelect` over the vaccine items visible to the logged-in store) · Include in GAPS calculations · Can skip dose (`Checkbox`) · **Dose**. The dose table is a `DataTable` with in-place cells (label `TextField`; from/to age as two `NumberField`s — years, months 0–11; custom age label; min interval whole days; a `TrashIcon` `IconButton`), every column structural. New doses take the spec'd defaults (`nextDose`). The completeness checks run from the start; the typed-value rules (dose order, too large) show the moment they trip, the required checks once the first Save press arms the form, all live after that — listed in an `Alert` above the table with dose failures grouped per dose, and on each failing field (`error`; the age pair as one `FieldShell` whose halves take `invalid`). Footer is `CancelButton` + `DialogSaveButton` — **Save, not OK** — always offered on create, only once dirty on edit; busy while saving. Success closes the dialog and the list refreshes; a refusal keeps the dialog open with the draft intact and the reason in an `Alert` in the dialog's `footer` slot (the raw server detail behind `ErrorDetails` for the generic case). Every save writes the whole course in one mutation; a Forbidden routes to the permission-denied modal.
- **S3a per-store rates panel** (`StoreRatesPanel.tsx`) — a second `Dialog` layered over the editor: a search field, a `Table` of the server's stores (`fill`: it takes the panel's height and scrolls its rows, so a full-screen dialog on a phone has no gap under them) with two `NumberField`s per row, **Back** (drops the panel's edits) · **OK** (hands them into the draft). The stores come from the **shared store lookup** (`domain/store` — `storePageFetcher` + `createPaginatedSearch`), so the search filters on the SERVER and the list pages as it scrolls; the vertical declares no store query of its own. It first read `first: 1000` and filtered in memory, which put every store past the thousandth beyond reach (PR #749 review, F1 — and what tables › pagination & scale forbids over an open-ended set).
- **S4 delete** (`DeleteCoursesAction.tsx`) — the list's one bulk action: `Dialog` with confirm → deleting → refused phases (not `ConfirmDialog`, which cannot hold the refused phase), count-pluralised permanence notice, danger OK. One `deleteVaccineCourse` per course, **sequential in list order, stopped at the first refusal** (`runDeletes`); the in-use refusal (`VaccineCourseInUse`) shows in the dialog's refused phase under _Can't do that!_; the list re-reads behind it; the selection clears when the dialog closes.
- **Permission mirror** — New vaccine course, the empty state's create action, Save and Delete refuse up front through one `guardEdit()` (`hasPermission('EDIT_CENTRAL_DATA')` → `reportPermissionDenied(['EditCentralData'])`), before any dialog opens or write is sent; a row click stays a read for everyone. The server's own Forbidden on any write routes to the same modal.
- **Wiring (additive only)** — `src/App.tsx` gains `'programs/immunisations': immunisationProgramsRoutes`; the `programs` section (`central`) and its `programs/immunisations` entry (`vaccineModule`) already existed in `src/nav/navConfig.ts` and were not touched. `Alt+N` registered once for S2 via `createAddAction`, badged on both the header button and the empty-state ghost.
- **No new locale keys.** Every key `ui-surface.md` cites resolved verbatim in `src/intl/locales/en/`, plural variants included (`messages.confirm-delete-vaccine-courses_*`). Nothing added to `fr/` or `ar/`.
- **Testids** — an _Immunisation programs_ section added to [`e2e/TESTIDS.md`](../../../e2e/TESTIDS.md) contracting the screen-specific ids; everything else is a shared id the library emits.

## Flags

- **⛔ roles used: none.** Standard list screen 🔶 · breadcrumbs `Breadcrumb` · page action `Button` · data table (list) `DataTable` · filter bar `FilterBar` · empty state (the table's own) · bulk-action bar 🔶 · modal dialog `Dialog` · labelled field row `FieldRow` · short text `TextField` · number `NumberField` · checkbox `Checkbox` · autocomplete `Combobox` · multi-select autocomplete `MultiSelect` · two-up form row `FormRow` · horizontal stack `HStack` · data table (detail lines) `DataTable` 🔶 · icon-only button `IconButton` · inline banner `Alert` · error detail disclosure `ErrorDetails` · static sub-table `Table` · modal footer buttons `CancelButton` / `DialogSaveButton` / `OkButton` · confirmation dialog composed on `Dialog` (as campaigns and the reference vertical — `ConfirmDialog` closes on confirm and cannot hold the refused phase).
- **A shared-reference bug caught only by the live drive.** Seeding the store and the "original" for the dirty test from the same course object meant a store write to a dose mutated the original in place, so Save never re-enabled on a dose edit; every node test passed because the tests used spread copies. Fixed by deep-copying both (`structuredClone`). Worth a `kdd/solid-reactivity-pitfalls` line: an "original for the dirty compare" must never share objects with a `createStore` draft.
- **`MultiSelect` keeps picked items listed and check-marked** (the library's WAI-ARIA multi-combobox model); `ui-surface.md` S3 says a chosen item "leaves the options" — the reference's Downshift behaviour. Registry contract wins; the spec sentence should follow.
- **S5's refusal placement.** `ui-surface.md` S5 puts the in-use delete refusal "in S2's footer"; this build shows it in the delete dialog's refused phase (title _Can't do that!_, `Close`), the house delete-dialog pattern every sibling uses. Candidate refinement below.
- **`Dialog`'s scrim.** AC-C11 wanted an outside click to leave the editor open; the library's `Dialog` dismisses on scrim click unless `dismissable={false}`, which also swallows Escape (OMS-REG-IMM-01.40 wants Escape to close). Not separable today; the scrim behaviour is the library's, left as is and flagged.
- **A tracked store read in a cell template remounts the cell.** The age pair's first version initialised its typed-state signal from `dose[field]` in the template body; that body runs inside the table cell's render effect, so the read was tracked at the cell level and every store write the pair made re-ran the template — new inputs, focus dropped, the next keystroke landing in a fresh field at the wrong caret. Only the two age cells remounted; the label, custom-label and interval cells read the store lazily inside attribute getters. `untrack` on the initial read fixed it; the effect owns the only tracked read. Worth a `kdd/solid-reactivity-pitfalls` line beside the store-aliasing one.
- **The shared table drew an empty toolbar row.** `DataTable` rendered its toolbar whenever the controls were not lifted elsewhere, even with nothing to put in it — this dose table (every column structural, no config, no full screen) got an empty bar whose bottom hairline read as a double line above the header, where the stocktake line table (controls lifted into the header) had one clean frame. Found by Aneesh's manual test; fixed in `DataTable` for every table in that state (create-patient, repack, prescription history and line modals, the indicators tab): the row renders only with a filter bar, a count, or a control to hold (ui-standards › tables › toolbar). The bottom edge had the same doubled seam without the gap — the last body row's hairline pressed against the frame — fixed in the same stylesheet: the last body row draws no bottom hairline, the band after it (frame, footer band, `<tfoot>`) owns the seam.
- **`MultiSelect` gained the error state the spec asks for.** ui-surface S3 wants each failing field in its own error state; the registry's `MultiSelect` took no `error`, so the vaccine-items field could only be named in the summary. It now takes `error`/`errorTestId` on `Combobox`'s anatomy — red border, `aria-invalid`, icon + text below — and the field uses it (PR #749 review, F7). Registry row updated.
- **Review fixes (PR #749), the ones that reach beyond this vertical.** `TextField` gained `invalid` (the error STATE without a message, for one half of a composite — the age pair's two halves under one `FieldShell`); `MultiSelect` gained `error`; `DataTable` draws no toolbar row when the cluster would be empty and keeps the refetch indicator in the table area when there is none, and its last body row draws no bottom hairline; the static `Table` takes an optional bounded height + `onReachEnd` for a sub-table fed by a paged read; the "near the bottom" threshold moved to `createPaginatedSearch` so the listbox and the sub-table share one figure; and the central-data permission guard both central screens had copied moved to `store/storeContext` as `guardCentralDataEdit`.
- **Two `solid/reactivity` lint suppressions, deliberate** — the editor reads `props.courseId`/`props.programId` and the panel reads `props.configs` once on mount, because each is mounted only while open and a rejected save must keep what the user typed.
- **C2 real-backend leg: covered, no CI home.** The Playwright drive that exercised every row marked ✅ lives in the run's scratchpad, not the repo. Nothing was mocked to make a behavioural claim.
- **⚠️ VERIFY items encountered: none.**

## Decisions the spec should make (candidate refinements)

1. **Page size.** `rules.md` says twenty to a page (the reference's figure). Every list in this app starts a fresh visit at the user's remembered rows-per-page, app default 50 (`@/list/pageSize`, D106), and this build follows that convention with 20 as the URL-state default only — as campaigns did. The spec should say "the standard list page size" or decide 20 is binding.
2. **Where the in-use delete refusal shows** (S5): the footer notice the spec names, or the delete dialog's refused phase the house pattern uses. This build uses the dialog.
3. **`MultiSelect` semantics** (S3 § vaccine items): picked items stay listed, check-marked — align the sentence with the registry.
4. **Escape vs. scrim** (OMS-REG-IMM-01.40 / AC-C11): the two criteria pull the shared `Dialog` in opposite directions; the spec should pick the library's contract (Escape and scrim both dismiss) or ask the library for a scrim-only opt-out.

5. **Fractional years** — resolved after the exploratory run (IMM-20260917-F2) and Aneesh's manual test: the years half of a dose's age is whole; months keep a fraction (week-based schedules; the server's due date is months × 30.44 days). Rules § input bounds and the README's captured-as-is carry it; the reference keeps decimals in both halves.
6. **When the checks report** — resolved with Aneesh's manual test (2026-09-17): the spec had the summary appear only after a Save press; the house standard (controls › form submits validate on click) and the reference both let a rule about what was typed report as it trips. Now the dose order rules and the too-large rate report as typed and the required family on Save (ui-surface S3, rules § the editor; `.53`, `.54`, `.64` reworded, ids kept). `TextField` gained an `invalid` flag so the age pair can sit in one `FieldShell` with one message.

**Resolved at the reconcile step (2026-09), each as a one-line spec edit awaiting QA/Product review with the PR:** 1 → the standard page size (rules § the program list / detail); 2 → the delete dialog's refused phase (ui-surface S5); 3 → a chosen item is shown as chosen and cannot be added twice (rules § vaccine items, `.33`); 4 → the library's contract — the scrim dismisses like Escape (rules § the editor; AC-C11 not folded, the reference's behaviour recorded as captured-as-is).
