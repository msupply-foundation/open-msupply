01 — MENTAL MODELWhat the table is, and isn't

The <DataTable> is presentational about data. It does not fetch, paginate, or sort rows — the page hands it the current page of rows already in the order it wants, and the table renders them. What it does own is presentation state: full-screen, the active tab, and the table-vs-card view mode.

Ownership splits cleanly, and it's worth holding this in your head before reading the props:

  • The page owns sort, selection, pagination, and the resolved column config. It hands them in and receives change callbacks — the same controlled shape as a form input.
  • The table owns full-screen, the active tab, and (through the config it's handed) the view mode and row-grouping toggle.
  • TanStack owns the row model, grouping/expansion, and aggregation. We render what it computes.

The component is generic over three type parameters, and every one is load-bearing — you'll see them throughout:

Type param Stands for Keeps honest
T The row type — usually a generated GraphQL node. A column's key must be a real field of T; a typo is a compile error.
K The sort-field union — the GraphQL sort keys. A column's sortKey and the onSort callback can only ever name a real sort field.
G The card-group keys (defaults to never — no groups). A column's tabsAndCardGroups can only list groups you actually declared.

02 — TABLE PARAMETERSEvery prop <DataTable> takes

The full DataTableProps<T, K, G>. Only three are required; everything else opts a capability in. Grouped by concern rather than alphabetised, because that's how you reach for them.

Data — required

Prop Meaning
columns requiredColumn<T, K, G>[]

The column definitions — the heart of the interface. Each drives one column's identity, header, cell rendering, sortability, and card/tab placement. Detailed in §3.

rows requiredT[]

The current page of rows, pre-ordered. The table never re-sorts them (manualSorting).

rowKey required(row: T) => string

A stable identity per row, used for selection and keyed rendering. Return the row's real id — never the array index.

Sorting — page-owned

Prop Meaning
sortSortState<K> | undefined

The current sort — { key, desc } — or undefined when unsorted. Drives the header's sort indicator.

onSort(key: K, desc: boolean) => void

Fired when a sortable header is clicked. TanStack computes the next direction in the asc → desc cycle; you just record key + desc (e.g. into URL state).

Interaction & display

Prop Meaning
onRowClick(row: T) => void

When set, a row becomes clickable (and gets a pointer cursor) — e.g. navigate, or open an edit modal. Omit for a static table.

emptyMessagestring

Shown in place of rows when there are none. Defaults to a translated “No results.”

showFullScreenboolean — default true

Show the full-screen toggle in the control bar. Pass false where full-screen makes no sense — e.g. a table inside a modal, whose shell isn't the one the toggle would expand. The card-switch and column-settings controls are unaffected.

Selection — page-owned

Prop Meaning
enableSelectionboolean

Turns on the per-row checkbox column (and the header select-all).

selectedIdsstring[]

The currently-selected row ids (by rowKey). Controlled by the page.

onSelectionChange(ids: string[]) => void

Fired with the next selection. The page renders the selection action bar in its own footer, not the table.

Card groups & row grouping — optional capabilities

Prop Meaning
tabsAndCardGroupsTabAndCardGroup<G>[]

Declares the group set. When present, the table shows a tab strip and renders only the active group's columns (plus any ALL_TABS anchors). In card view the same groups become the card's labelled sections. The table owns which tab is active — no state leaks to the page. See §6–7.

rowGroup{ columnId: string; labelKey: LocaleKey }

A different concept from card groups: collapses rows that share a value under one expandable parent (e.g. all of an item's batches). Names one column to group by; the toolbar shows a single on/off toggle. See §8.

Column layout config — page-owned, optional

Prop Meaning
configTableConfig

The resolved column order / sizing / pinning / visibility, plus view mode and grouping. The page resolves its three layers (default → global → user) into one value — see §9. Omit and the table uses TanStack's defaults from columns.

setConfig<K>(key, value) => void

Called with the resolved next value for one config field when the user reorders, resizes, hides, pins, switches view, or toggles grouping. Controlled exactly like onSort.

03 — THE COLUMN DEFINITIONOne Column<T, K, G>, four responsibilities

Every column is one object. It replaces TanStack's raw accessorKey/accessorFn/id with a single nested c identity field (so identity is spelled exactly one way and can be typed), then carries the rest of TanStack's column fields plus two of our own extensions.

src/ui/elements/table/columnTypes.ts 
export type Column<T, K extends string, G extends string = never> = {
  c: ColumnIdentity<T>;              // identity: key | id | accessor (see §4)
} & Omit<IdentifiedColumnDef<T>, 'id'> & {
  sortKey?: K;                       // the GraphQL sort field this column sorts by
  tabsAndCardGroups?: G[] | typeof ALL_TABS;  // tab / card-group membership
};

Unpacking the four responsibilities each column object carries:

Field Role
cColumnIdentity<T>

Identity. How the column finds its value and what its id is. Nested under its own field so it never mixes with display fields. Three forms — §4.

headerstring | JSX | fn

The column heading. Use a string — card view reuses it as the field label, and only the string case yields a readable one.

cell(info) => JSX

Renders the body cell. Omit for a plain text column (TanStack renders the resolved value as-is); provide it to format or to render an editable control. Receives info.getValue() and info.row.original.

metaColumnMeta

Untyped display conventions — align, wrapLines, and the card region. These need no table-specific type, so they ride TanStack's meta bag (§5–6).

sortKeyK

The GraphQL sort field. Kept separate from identity because a column may sort by a different field than it displays. Usually equals the column's key.

tabsAndCardGroupsG[] | ALL_TABS

Which tab(s) / card group(s) this column belongs to (§7). Omit and the column has no group — in card view it falls to the ungrouped area.

aggregationFnTanStack AggregationFn

What the grouped-parent cell shows when rows are grouped (§8). Set directly (the cell helpers set sensible defaults).

The typed-vs-untyped rule

A display convention that needs no table-specific type (alignment, wrap, card region) lives in meta. A convention that needs the K or G generic to stay honest (sortKey, tabsAndCardGroups) is a typed field on Column itself — because ColumnMeta can't carry those generics.

04 — COLUMN IDENTITYThe c field — three shapes, one per real case

ColumnIdentity<T> is a discriminated union. A column is exactly one of these, and the mapper toColumnDef turns each into the matching TanStack fields, always stamping an explicit id.

src/ui/elements/table/columnTypes.ts 
export type ColumnIdentity<T> =
  | { key: keyof T }                       // reads that field · natively sortable · id = the key
  | { id: string }                         // a display column — no value read (actions, checkbox)
  | { accessor: (row: T) => unknown; id: string };  // a computed / nested value + an explicit id
Form When Example
{ key }

The common case. A keyof T — a real field. The column reads it, is natively sortable, and its id is that key.

c: { key: 'batch' }
{ id }

A display column with no data accessor — an actions column, a checkbox. Just a unique id.

c: { id: 'actions' }
{ accessor, id }

A computed or nested value — row.item.code, a derived string. An accessor plus an explicit id, since there's no key to derive one from.

c: { accessor: r => r.item.code, id: 'code' }

Because every column ends up with a known id, the sortKey ⇄ id round-trip (for the controlled manual sort) and the column-layout config both have a stable handle to key by.

05 — CELL HELPERSFragments you spread into a column

A plain text column needs no cell — { c: { key }, header, sortKey } renders as-is. For the common formatted types, tableHelpers exports fragments you spread in. Each sets only what differs from a plain column (alignment via meta, a formatting cell, and a sensible grouped-parent aggregationFn).

src/ui/elements/table/tableHelpers.ts 
getNumberCell()   // right-aligned; grouped parent → SUM of leaves
getDateCell()     // localised date, blank → em dash; parent → shared date or [multiple]
getBooleanCell()  // resolved value → localised Yes / No

// spread into a column literal:
{ c: { key: 'snapshotNumberOfPacks' }, header: t('…'), sortKey: 'snapshot', ...getNumberCell() }

Why fragments, not a column factory

Each helper returns a narrow fragment typed off ColumnDefBase — only the fields it sets — so it spreads into a Column of any (K, G), including a groups-only edit table whose K is never. Explicit composition over a config object: you see exactly which fields each helper contributes.

06 — CARD AREASHow a column places itself on a card

In card view, each row becomes a card and every visible cell is routed to one of three areas by its meta.card region. A column with no card falls into the secondary area below the header. the three placements, in column definitions 
// PRIMARY — the card title. showLabel reuses the header as a caption.
{ c: { key: 'batch' }, header: t('…batch'),
  meta: { card: { region: 'primary', showLabel: true } }, cell: … }

// BADGE — the top-right chip.
{ c: { key: 'snapshotNumberOfPacks' }, header: t('…snapshot'),
  meta: { card: { region: 'badge' }, align: 'right' } }

// SECONDARY — no card key at all → drops below the header as a label-value pair.
{ c: { key: 'expiryDate' }, header: t('…expiry'), ...getDateCell() }

Visibility still applies

A card only shows cells the column config leaves visible — a hidden column doesn't appear on the card either. The card is a re-layout of the same visible cells, not a separate render path with its own rules.

07 — TABS & CARD GROUPSOne membership, two faces

A card group is a set of columns that belong together — “Batch”, “Pricing”, “Other”. The same declaration drives two faces: in table view each group is a tab (only the active group's columns show); in card view each group is a labelled section row on the card, led by its icon. Hence the field name: tabsAndCardGroups.

declare the groups once (the page owns this list) 
type GroupKey = 'batch' | 'pricing' | 'other';   // this is the G generic

const TABS_AND_CARD_GROUPS: TabAndCardGroup<GroupKey>[] = [
  { key: 'batch',   labelKey: '…tab-batch',   icon: () => <StockIcon /> },
  { key: 'pricing', labelKey: '…tab-pricing', icon: () => <InfoIcon /> },
  { key: 'other',   labelKey: '…tab-other',   icon: () => <MessageSquareIcon /> },
];

Then each column names its membership. Three shapes:

On the column Table view Card view
tabsAndCardGroups: ['batch'] Shows only on the Batch tab. In the Batch section row.
tabsAndCardGroups: ALL_TABS Shows on every tab — a row-identity anchor (the batch, the checkbox). Falls to the ungrouped area (unless it has a card region).
omitted Not part of any tab. The ungrouped row at the bottom of the card.

Table view · the groups become tabs

Batch Pricing Other
☑ Batch Expiry Location Snapshot
☑ 26F113 31/05/2026 Room A 2,600

The Batch tab is active, so only the checkbox + batch (ALL_TABS anchors) and the columns tagged ['batch'] show. Switching to Pricing swaps in the price columns; the anchors stay.

Filter, not visibility

The active-tab filter is a secondary filter applied before columns reach the table — deliberately separate from the user's persisted columnVisibility, so switching tabs never rewrites their saved column layout. The table owns the active tab internally; it never leaks to the page.

08 — ROW GROUPINGA different axis: collapsing rows

Not to be confused with card groups. Row grouping collapses rows that share a value under one expandable parent — every batch of one stocktake item under that item's row. It's TanStack's grouped + expanded row models; the table renders what they compute.

Row grouping · parent aggregates its leaves

Item Batch Expiry Snapshot
▾ Amoxicillin 250mg [multiple] [multiple] 217
26F113 26F113 31/05/2026 130
B50046 B50046 30/06/2026 87
Paracetamol 500mg PK7397 29/02/2028 16,000

The parent's Snapshot is getNumberCell's sum aggregation (217 = 130 + 87); the date and batch differ across leaves so they show the [multiple] sentinel. A group with a single leaf (Paracetamol) isn't expandable — it renders as a plain row.

Each column decides what its parent cell shows via its aggregationFn:

aggregationFn Parent shows
'sum' (getNumberCell default) The sum of the leaf values.
sharedOrMultiple The one shared value if all leaves agree, else [multiple].
sharedOrMultipleDate (getDateCell default) Same, comparing dates by epoch-ms; the parent formats identically to a leaf.

Grouping is static and page-declared (one rowGroup.columnId); a toolbar folder-icon toggles it on and off, and that on/off state lives in the table config — so it persists and layers per breakpoint just like the view mode.

09 — LAYOUT CONFIGOrder, size, pinning, visibility, view mode

TableConfig is the user-tunable layout. The four column-state fields are exactly TanStack's own state shapes — no remapping — so a stored config feeds state.* directly. Two more fields are view-level choices the table reads directly.

src/ui/elements/table/tableConfig.ts 
export type TableConfig = {
  columnOrder?: ColumnOrderState;       // column left-to-right order
  columnSizing?: ColumnSizingState;      // per-column widths
  columnPinning?: ColumnPinningState;    // left / right pinned columns
  columnVisibility?: VisibilityState;    // sparse "show": absent = visible, false = hidden
  viewMode?: ViewMode;                   // 'table' | 'card'
  groupBy?: string;                      // grouped column id, or absent = ungrouped
};

Three layers, per breakpoint

The page resolves the effective config from three precedence layers — user (localStorage) > global (a store-wide blob over GraphQL) > default — and does it per breakpoint band, with no cross-band fallback. Each field is taken whole from the first layer that provides it, so a user who only reordered still inherits the global widths. This is createTableConfig, itself a store-scoped resource.

10 — FULL EXAMPLEA column set using every feature

Distilled from the stocktake line-edit table — the richest real consumer. Note the generics: Column<DraftLine, never, GroupKey> — a groups-only table (K is never: it's not server-sorted), grouped into batch / pricing / other.

src/sections/stocktakes/detail/edit-modal/StocktakeLineEditModal.tsx 
const columns = (): Column<DraftLine, never, GroupKey>[] => [
  {
    c: { id: 'countThisLine' },              // display column, no data read
    header: t('…count-this-line'),
    tabsAndCardGroups: ALL_TABS,             // anchor: first column of every tab
    meta: { align: 'center' },
    cell: info => <input type="checkbox" … />,   // editable cell
  },
  {
    c: { key: 'batch' },                     // keyof DraftLine — typo = compile error
    header: t('…batch'),
    tabsAndCardGroups: ALL_TABS,
    meta: { card: { region: 'primary', showLabel: true } },  // card title
    cell: info => <TextField … />,
  },
  {
    c: { key: 'expiryDate' },
    header: t('…expiry'),
    tabsAndCardGroups: ['batch'],             // Batch tab / Batch card section
    cell: info => <TextField type="date" … />,
  },
  {
    c: { key: 'sellPricePerPack' },
    header: t('…sell-price'),
    tabsAndCardGroups: ['pricing'],           // Pricing tab / Pricing card section
    ...getNumberCell(),
  },
  {
    c: { key: 'snapshotNumberOfPacks' },
    header: t('…snapshot'),
    tabsAndCardGroups: ['batch'],             // read-only reference figure, in the Batch group
    cell: info => <span>{info.row.original.snapshotNumberOfPacks ?? '—'}</span>,
  },
  {
    c: { id: 'actions' },                   // display column (duplicate + delete buttons)
    header: t('common.action'),
    tabsAndCardGroups: ALL_TABS,             // last column of every tab
    meta: { card: { region: 'badge' }, align: 'right' },  // card badge: the action buttons
    cell: info => <RowActions … />,
  },
];

// …then rendered:
<DataTable
  columns={columns()}
  rows={draftLines()}
  rowKey={line => line.id}
  tabsAndCardGroups={TABS_AND_CARD_GROUPS}
  enableSelection
  showFullScreen={false}          // inside a modal
/>

That one array renders as a sortable table, a three-tab table, or a stack of cards with a titled batch, an actions badge, and Batch / Pricing / Other sections — all decided by the fields above, no separate markup per face.
