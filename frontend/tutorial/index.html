Developer Tutorial

The open-mSupply frontend, from the state up

This is a hands-on tour of how the SolidJS front end is wired — its data flow, its global state, and the small set of deliberate patterns everything is built from. By the end you could re-create the front end from scratch. The focus is functionality and state, not styling or components.

How to read this

Six chapters, in dependency order. Each one builds a small example vertical called widgets/ — from an empty .graphql file to a working list-and-detail screen — introducing each pattern exactly when the build needs it. This mirrors how the app's real reference vertical, src/sections/stocktakes/, is put together. Every chapter points back to the real file it is distilled from.

The widgets/ code is a teaching device — it does not exist in the repo. When you want to see a pattern in production, follow the Real code links to src/.

The app in one picture

There is no Redux, no Apollo/urql, and — perhaps surprisingly — no React-style provider tree or createContext. Global state is just module-level SolidJS signals, imported directly. Data flows one way: the URL and user actions drive query variables; a single never-throwing fetch turns those into typed results; errors are values handled once, globally.

Two ideas run through everything

You will see these repeatedly rather than as their own chapters — they are the codebase's taste, distilled from its Key Decision Documents (KDD):

  • Maximum type safety through codegen. Every piece of state is derived from a generated GraphQL type — never remapped to a parallel shape. A filter is the generated filter input; a row is Result['nodes'][number].
  • Explicit composition, refresh by direct call. No cache keys, no event bus, no subscriber registry. When something needs to refresh, whatever observed the need calls the specific refetch function — click-through traceable.

One doc-drift to know about

A few source docstrings refer to codegen/plugin.js and codegen/run.js; the actual files are .cjs (codegen/plugin.cjs, codegen/run.cjs). This tutorial uses the real filenames.
