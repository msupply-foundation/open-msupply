# UI elements — what each is built from

A living ledger of every UI element built in this app and **what went into it** — hand-rolled plain HTML/CSS vs. a headless library part, and *why* a library was used where it was. Update this whenever an element is added or its composition changes. (Same convention as the RnD prototype's `UI_ELEMENTS.md`.)

> **Convention.** Default is **hand-rolled**: plain semantic HTML + CSS Modules + design tokens (`src/styles/tokens.css`), sized in rem. We reach for a **headless** primitive only where the widget has a real accessibility/interaction contract that's tedious and risky to hand-roll (and that WCAG 2.2 grades). When we do, **we still own all the markup and CSS** — the library supplies behaviour + ARIA, not a look.
>
> **The WCAG 2.2 AA bar applies to every element in this table, hand-rolled or headless** (principle #9 in `CLAUDE.md`). Buying a headless primitive is how we meet it for the hard widgets; it is not the only place a11y matters. Hand-rolled elements owe the same duties — semantics + accessible name, keyboard operability, visible focus, AA contrast in both themes, no colour-only meaning.

## Elements

| Element / part | Built with | Headless dep — and why |
|---|---|---|
| **Storybook shell** — header, section nav, panel | Hand-rolled (`showcase/ShowcaseApp.tsx`: grid layout, `<nav>`/`<ul>`/`<a>` with `aria-current`) | — Active section lives in the URL hash (`#/buttons`) via plain anchors + one `hashchange` listener; no routing library (routing is undecided). Each section has a `kind`: `'component'` (default) renders inside the padded panel; `'page'` renders **full-bleed** (see below). Lives in `src/showcase/` with all other demo scaffolding — the library (`src/components/`) and real pages (`src/pages/`) never import from there; `index.tsx` mounts it while the library is the app (see `DECISIONS.md` 2026-07-08 separation entry). |
| **Full-bleed page mode + Showcase launcher** — how whole-page layouts are demoed | Hand-rolled (`showcase/ShowcaseApp.tsx` `<Show>` branch on `kind`; `showcase/ShowcaseLauncher`) | — A `kind: 'page'` section drops the showcase chrome and lets the component own the real viewport, so it can be resized / device-tested without a competing frame (an iframe canvas was rejected for exactly that reason — see `DECISIONS.md` 2026-07-07). The **ShowcaseLauncher** is a fixed floating `<button>` + `<Show>` popover (section links reusing the hash nav, plus the ThemeToggle, Escape-to-close) — the escape hatch back to the menu. `kind: 'app'` (real pages, e.g. `#/home`) is full-bleed with **no launcher either** — zero showcase chrome, exactly as a build would ship the page; browser Back returns to the showcase. |
| **Application shell** (`components/layout/AppShell`) — the app-level container | Hand-rolled (flex row: MenuBar + main column of the **content slot** (the current page) and the **orange app footer**) | — Pure layout + tokens, and **the container the main menu lives in — not the pages** (see `DECISIONS.md` 2026-07-08 page-pattern entry): one AppShell mounts per host and pages swap inside its content slot, so menu state (rail collapse, overlay) survives navigation. Per-page geometry (pinned header, scrolling body, side panel, content footer) belongs to the **Page frame** the page composes — the shell's former `header`/`contentFooter` slot props moved there. The one responsive decision (docked rail vs. hamburger overlay) is a "which element renders" branch driven by `useIsNavOverlay` (JS `matchMedia`), per principle #7; the shell provides `ShellNavContext` (isOverlay + openNav) so the hamburger renders inside the page's Header strip. Footer is the current app's orange status bar (General / Edit / demo / language / Central server) — `--primary-main` ground, white content via `color-mix` for the hover/divider tints. **Controlled**: `selected`/`onNavigate` — the host owns nav selection (a router eventually; `pages/Home` and `pages/OutboundShipments` hold it in a signal for now). Adapted from the RnD prototype's App shell. |
| **Page frame** (`components/layout/Page`) — the page-pattern geometry | Hand-rolled (flex column: `header` slot / middle row of scrolling body + `sidePanel` slot / `contentFooter` slot) | — **Geometry only** — the structural contract every list/detail-style page shares, with zero opinion about slot contents: the frame owns where regions sit and what scrolls (body only; header/panel/footer pinned), regions own their own look, optional slots collapse (list and detail are one frame, not two templates). Pages compose it inside an AppShell and own **no CSS of their own** (enforced by `scripts/check-page-css.mjs` in `npm run check`). The canonical assemblies are the `pages/OutboundShipments` skeletons. See `DECISIONS.md` 2026-07-08. |
| **Side panel** (`components/layout/SidePanel`) — SidePanel + SidePanelSection | Hand-rolled (`<aside>` docked in the Page frame's `sidePanel` slot, own scroll; divider-separated `<section>`s; field rows are plain `<dl>` dt/dd pairs styled by the panel's CSS) | — The detail-view right-hand panel (the current app's DetailPanel: additional info, related documents, comments). Pure layout, zero state — the page composes sections and owns the data. **Known gap (skeleton stage):** below the nav-overlay breakpoint the docked panel doesn't render (which-element media decision); the current app's toggled overlay drawer replacement needs Drawer, which arrives with the Feedback work. |
| **MenuBar** (`components/layout/AppShell/MenuBar`) — the main menu, two modes | Hand-rolled (`<nav>`/`<ul>`, `<button>` nav items with `data-selected`/`data-active`, `aria-expanded` collapsible sections; overlay panel + scrim) | — One component, two layouts: **docked** (icon-rail collapsible via the logo button) and **overlay** (off-canvas panel + scrim below the `navOverlay` breakpoint), sharing the same nav lists. Collapsible sections are a plain signal + `<Show>` (no Collapsible primitive — it's just show/hide, no focus/ARIA contract worth buying). Item layout matches the current app: `[icon][chevron·or·slot][label][end-chevron]`, 40px rows, label `--text-body`, orange active parent, orange end-chevron on the selected item. RTL via logical properties. Nav items are inert buttons in the demo (no router yet). Renamed from `Sidebar` (Carl, 2026-07-08) — **the "Sidebar" name is reserved for a different, future element**; don't reuse it for the menu. |
| **LanguageSelector** (`components/layout/AppShell/LanguageSelector`) — footer language picker | Our markup + CSS over Kobalte DropdownMenu (Trigger/Portal/Content/Item) | **Kobalte DropdownMenu** — a menu popup with focus management, type-ahead and arrow/Escape keyboard nav worth buying; styled via `data-*` (`data-highlighted`, our `data-current`), opens upward (`placement="top-start"`) out of the footer. Native language names, RTL-tagged, ported from the prototype's Radix version. Picking an RTL-tagged locale (ar/prs/ps) flips the whole document to RTL — the host (AppShell, and the Login page the same way) sets `dir` on `<html>` and restores `ltr` on unmount. Hover/focus tints derive from `currentcolor`, so the trigger works on any surface (white-on-dark in the footer, dark-on-light on the login panel). |
| **Page header** (`components/layout/Header`) — Header + HeaderButtons + Toolbar | Hand-rolled (one flex-wrap `<header>` strip; the parts slot themselves via their own CSS — HeaderButtons `margin-inline-start: auto`, Toolbar `flex-basis: 100%`) | — The page-top atom (the current app's AppBar): breadcrumb inline-start, page actions inline-end, per-page toolbar on its own full-width row. **Pure layout, zero state** — the page composes `<Header><Breadcrumb/><HeaderButtons/><Toolbar/></Header>` and owns the trail data and action handlers. Squeezed, the buttons wrap intrinsically below the breadcrumb (no breakpoints, principle #7). Toolbar is deliberately **not** `role="toolbar"` (that role demands roving-focus arrow-key semantics — wrong for a loose filter strip). Inside an AppShell the **overlay hamburger renders at the strip's start automatically** (via `ShellNavContext`; standalone headers, e.g. the showcase panel, never show one), and the page hands the composed header to the Page frame's `header` slot. Ported from the RnD prototype's Header, tab strip included: a `ui/Tabs` **TabList as the last child becomes the header's bottom edge** — `Header.module.css` matches `:has(> [data-tab-bar])`, drops its own border/bottom padding and pulls the strip out to its edges, so the strip's border runs edge to edge as in the demo. |
| **Breadcrumb** (`components/layout/Header/Breadcrumb`) | Hand-rolled (WAI-ARIA breadcrumb pattern: `<nav aria-label="Breadcrumb">` > `<ol>`; ancestor crumbs with `to` are bold `<a>` links, the leaf is the page's **`<h1>`** with `aria-current="page"`, styled as just another crumb; `/` separators are `aria-hidden` list items; optional brand-orange section icon) | — Links + separators carry no interaction contract worth buying. The trail is a plain `crumbs` prop — page-owned now, route-derived once routing lands; a crumb's interim `onClick` (added for the detail → list back-navigation while views swap via local state) renders as a link and gets replaced by a real routed href later. **The leaf is the page's single h1** (decided at shell integration, 2026-07-08 — the page title lives in the breadcrumb tail, as in the current app; pages must not render another h1). Ported from the prototype's Breadcrumbs (leaf was a plain span there). |
| **Tab bar** (`components/ui/Tabs`) — Tabs + TabList + TabPanel | Our markup + CSS; the sliding underline is our own measured-geometry indicator (the one legit px use — computed layout, not a design token; re-measures on tab change, window resize and webfont load). `TabList` reads the active tab from Kobalte's context — no `value` prop | **Kobalte Tabs** — the WAI-ARIA tabs pattern + roving tabindex + ←/→/Home/End + automatic activation + tab↔panel wiring; inactive panels unmounted; the panel is a tab stop only when nothing inside it is (upgrade over Radix). Tiny; no Floating UI. Solid analogue of the prototype's Radix Tabs. Kobalte's own `Tabs.Indicator` rejected (no re-measure on container resize → stale underline on a centred strip), and its missing `aria-labelledby` on the initially selected panel is patched by passing it explicitly — see `DECISIONS.md` 2026-07-08. The indicator re-measures via a **ResizeObserver on the strip** (a window resize listener fired before the menu bar's docked↔overlay swap reflowed the strip, stranding the underline), plus tab change and webfont load. The root is **`display: contents`** (a state boundary, not a layout box) so a `<Tabs>` can wrap a `<Page>` frame from outside — TabList in the header slot, panels in the body. Rendered as a Header's last child it becomes the header's bottom edge (see the Page header row). |
| **Table** (`components/ui/Table`) — display shell | Hand-rolled (scroll-wrap `<div>` + real semantic `<table>`; page composes `<thead>`/`<tbody>`; cell/row variants are **data attributes** — `data-numeric`, `data-check`, `data-muted`, `data-mono`, `data-selected`, `data-row-link`) | — **Display only, deliberately engine-agnostic**: the app's row look (toolbar-grey header row, hairline dividers, hover + selection tints) with no sorting/pagination/column state — per principle #4 that engine is **TanStack Table's headless core**, which renders into exactly this markup when it lands. `data-row-link` is a real `<button>` in the first data cell, so opening a row is keyboard-operable (the current app's click-only rows aren't). Selection tint never stands alone — the row checkbox carries the state. Replaces the App shell demo's hand-rolled table. |
| **EmptyState** (`components/ui/EmptyState`) | Hand-rolled (centred `<p>` + optional call-to-action children, filling its container) | — The current app's NothingHere: quiet centred text for unbuilt pages, empty/filtered-to-nothing tables, empty tabs. |
| **Content footer** (`components/layout/ContentFooter`) — ContentFooter + ContentFooterActions | Hand-rolled (one flat flex-wrap strip, `--bg-white` ground + hairline top border; ContentFooterActions pins itself inline-end via `margin-inline-start: auto`, mirroring HeaderButtons) | — The pinned action bar between a page's scrolling body and the orange app footer (the current app's blue-buttons bar: History / Cancel / Save, or "N selected" + selection actions). **Pure layout, zero state** — same contract as Header: the page composes the content, owns every handler, and hands the bar to the Page frame's **`contentFooter` slot** so it never scrolls with the body. **Contextual content is composition, not a store**: the page swaps the children with a `<Show>` on its own selection signal — the prototype's zustand `selectionFooter` store is deliberately not carried over (see `DECISIONS.md` 2026-07-08). A plain `<div>`, not `<footer>` — the orange bar is the page's one footer landmark. Save's confirm dialog isn't ported yet (Dialog arrives with the Feedback components). |
| **Login page** (`pages/Login`) — gradient hero + form panel | Hand-rolled layout (flex 50/50 split; hero = gradient `<section>` with the strapline `<h1>`, form panel composes library TextField / Button / LanguageSelector under the MSupplyGuy logo) | — Recreated from the current app's `LoginLayout` (see `DECISIONS.md` 2026-07-08): copy, 156° gradient, logo-width form column and bottom-left hero placement are from source; colours land as the `--gradient-primary` / `--bg-login` / `--login-hero-text` contract tokens. Hero type is fluid (`clamp()`), and the hero simply doesn't render < 600px (principle #7). Submit is disabled until both fields are filled and navigates to `#/home` (no auth yet); store selector, error panel and password-visibility toggle arrive with the auth/Feedback work. One AA-over-fidelity deviation: the version line is `--text-secondary`, not the original's failing `opacity: 0.4`. |
| **List + Detail skeleton pages** (`pages/OutboundShipments`) — ListView, DetailView, host | Composed entirely from library elements (AppShell › Page › Header family / FilterBar / Table / SidePanel / ContentFooter / Tabs / EmptyState) — **zero page CSS**, placeholder data in `demoData.ts` | — The canonical **page-pattern recipes** (`#/outbound-shipments`; see `DECISIONS.md` 2026-07-08): the list page (FilterBar toolbar live-filters the rows; selection swaps in the contextual footer) and the detail page (Tabs wrapping the frame, docked SidePanel, detail-action footer), with a host mounting ONE AppShell and swapping list ↔ detail inside it — the router stand-in, and the demonstration that the menu lives in the container, not the pages. New list/detail pages start as a copy of the matching recipe. |
| **Theme toggle** (sun/moon) | Hand-rolled (`components/ThemeToggle`) | — Just a `<button>` (with `aria-pressed`) that flips `data-theme` on `<html>` and persists to `localStorage`; a pre-paint script in `index.html` prevents a light flash. The `[data-theme='dark']` token block in `tokens.css` recolours everything via the cascade. |
| **Select** — styled drop-down (`components/ui/Select`) | Our markup + CSS over Kobalte parts (Trigger/Value/Content/Listbox/Item) | **Kobalte Select** — options need rich content (status dot, two-line label) a native `<option>` can't hold, and the replacement is a full `role="listbox"` popup with typeahead + keyboard/focus semantics that WCAG 2.2 grades. Solid analogue of the prototype's Radix Select; styled via `data-*` state attributes. API mirrors the prototype (string `value` in/out). |
| **Combobox** — autocomplete (`components/ui/Combobox`) | Our markup + CSS (search icon, hand-rolled clear button) over Kobalte parts | **Kobalte Combobox** — THE buy-don't-build widget (`aria-activedescendant` virtual focus, SR announcements, arrow/Enter/Escape semantics). Replaces Downshift `useCombobox`; upgrade over the prototype: popup is portaled with collision-aware, control-width placement. We supply the (locale-aware, code-or-name) filter predicate. |
| **MultiSelect** — multi-select autocomplete (`components/ui/MultiSelect`) | Our markup + CSS (tags rendered via Kobalte's Control render-prop state) over Kobalte parts | **Kobalte Combobox `multiple`** — replaces Downshift `useMultipleSelection`+`useCombobox`. Backspace removes the last tag, menu stays open across picks (Kobalte defaults). Delta from the prototype: picked items stay in the list check-marked (click to deselect) instead of dropping out — see `DECISIONS.md` 2026-07-07. |
| **FilterBar** — "Filters" dropdown + inline filter chips (`components/ui/FilterBar`) | Our markup + CSS (bordered select-style triggers, text chip with search icon, count badge, round remove buttons) over Kobalte DropdownMenu ×2 | **Kobalte DropdownMenu** — same buy as SplitButton/LanguageSelector (menu focus management, typeahead, arrow/Escape). The current app's FilterMenu model, ported from the prototype's Radix FilterBar: the menu lists available fields, picking one adds an editor chip — a text input, or a multi-check enum menu (`CheckboxItem` + `ItemIndicator`, `closeOnSelect={false}` so several tick in a row), plus "Remove all filters". **Values are a controlled prop** (`values`/`onChange` — parent-owned, destined for URL params once routing lands); chip visibility is local, seeded from `values` — see `DECISIONS.md` 2026-07-08. |
| **Button** — action button (`components/ui/Button`) | Hand-rolled (plain `<button>` + CSS Modules + tokens; `createRipple`/`Ripple` for the click ripple) | — Nothing to buy: it's a native `<button>`, so role + accessible name + keyboard/Enter/Space + `disabled` come free. White pill, no border, shadow[2]; `data-color` picks the tone — **orange** (brand, default) or **blue** (action, footer edits); fills with its colour on hover (label + icon → white). `iconPosition="end"` puts the icon after the label (login's arrow) — a CSS `order` flip, so AT reading order is untouched. Faithful Solid port of the RnD prototype's `<Button>`. |
| **SplitButton** — action + dropdown caret (`components/ui/SplitButton`) | Our markup + CSS (two `<button>` halves, 1px divider, per-half ripples) over Kobalte DropdownMenu (Trigger/Portal/Content/Item) | **Kobalte DropdownMenu** — the caret opens a menu popup whose focus management + type-ahead + arrow/Escape nav are the dangerous-to-hand-roll part (same call as the footer LanguageSelector, 2026-07-08). The main half runs the selected action; picking a menu item selects **and** runs it (the app's SplitButton/ExportSelector model). Caret open state styled via Kobalte's `data-expanded`; menu portaled to `<body>` so it inherits `dir` for RTL. Solid port of the prototype's ExportButton, generalised. |
| **Ripple** — click ripple (`components/ui/createRipple` + `Ripple`) | Hand-rolled: `createRipple` primitive (signal of active ripples + `onPointerDown`) feeding a `<Ripple>` render layer; CSS keyframes | — **The one deliberate JS-for-interaction exception** (everything else is pure CSS). The ripple must start at the exact pointer coordinates, which CSS can't read — so JS supplies each ripple's px position/size (dynamic pixel offsets, not layout spacing) and spawns one element per click; the animation stays CSS. Skipped under `prefers-reduced-motion`. Tint is the host's `--ripple-color` (set per button state via `color-mix`, so it tracks the theme). Solid port of the prototype's `useRipple`. |
| **TextField** — text input (`components/ui/TextField`) | Hand-rolled (plain `<label>` + `<input>` + CSS Modules + tokens) | — Nothing to buy: native input semantics, `label[for]` + `aria-describedby` wiring for helper/error text, `aria-invalid` + icon-and-text error message (no colour-only meaning), asterisk on the label for required. The company input design spec: token heights (default/small), short/long/full width caps, orange focus glow (`--focus-ring`), **red error glow via the new `--focus-ring-error` contract token** (the prototype hard-coded this rgba — tokenised per the no-hard-coded-colours rule). Solid port of the prototype's TextField. |
| **Icons** (`components/icons`) | Hand-rolled plain SVG (chevron, check, close, search; action set — plus/download/save/trash/alert-triangle/x-circle/copy/minus-circle/arrow-right; nav set — stock/truck/customers/thermometer/file/clock/reports/list/sliders/settings/radio/help; footer set — home/edit/user/translate/central; filled hamburger; MSupplyGuy logo) | — Copied wholesale from the current app (via the prototype's port): same Fill/Stroke `currentColor`/`1em` convention; only the icons actually in use, added as needed. The hamburger is the app's **filled** MUI Menu bars (not a stroked outline). The MSupplyGuy logo is the full 5-path original (body + arm + register box) and keeps its own orange→red brand gradient rather than `currentColor`. **Directional icons** (arrow-right) carry `data-flip-rtl`; a global `[dir='rtl']` rule in `index.css` mirrors them — the plain-CSS analogue of the app's `RtlFlipIcon` wrapper. |

## Cross-cutting (not a single element)

- **Design tokens** — `src/styles/tokens.css`, ported from the RnD prototype (itself a faithful port of the current app's `theme.ts`), restructured with an enforced **theme contract** region (see `DECISIONS.md` 2026-07-06). Includes the dark theme with the inverted-surface elevation model (`--surface-raised`, near-black dark shadows).
- **Root stylesheet** — `src/index.css`: box-sizing reset, the single root font-size knob (rem scaling; phone < 600px drops root to 85%), body defaults from tokens, Inter Variable via `@fontsource-variable/inter`.
- **CSS integrity tooling** — `npm run check`: typed-css-modules `.d.ts` generation → `tsc -b` → stylelint (incl. unknown-`var()` detection against `tokens.css`) → theme-contract script → page-CSS check (`scripts/check-page-css.mjs`: pages own no CSS — see `DECISIONS.md` 2026-07-08). See `DECISIONS.md` (2026-07-06).
- **Responsive primitive** — `hooks/createMediaQuery.ts` (a `matchMedia` → Solid signal) + `styles/breakpoints.ts` (`navOverlay: 1024`, `compact: 600`). The **only** JS that touches responsiveness, and only for "which element renders" decisions (principle #7); everything visual stays in CSS. Ported from the prototype's `useMediaQuery`/`breakpoints`.
- **Favicon** — `public/favicon.svg` is the MSupplyGuy brand mark (same paths/gradient as the `MSupplyGuyLogo` icon), replacing the Vite/Solid default so the browser tab matches the app.

## Dependencies

- **Runtime:** `solid-js`, `@fontsource-variable/inter` (font asset only), `@kobalte/core` (headless behaviour + ARIA for the selector family, the DropdownMenu buys and the tab bar — provisional, see `DECISIONS.md` 2026-07-07).
- **Dev-only tooling:** `typed-css-modules`, `stylelint` (+ `stylelint-config-standard`, `stylelint-value-no-unknown-custom-properties`), `concurrently`.
